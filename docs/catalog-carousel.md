# Compact catalog and reference inquiries

The homepage and `/models` share a native horizontal carousel: 240px cards, square image areas, 430px card height, two-line titles, single-line creator/license/category, and a bounded row. Wide screens show several cards; narrow phones show a full card plus a visible next-card edge. No carousel dependency is installed. Arrows move approximately one viewport, the focused rail supports Arrow Left/Right and Home/End, trackpad horizontal gestures and touch swipes stay native, and Shift+wheel scrolls horizontally only while the rail can move. Ordinary vertical-wheel page scrolling is preserved. Reduced-motion preferences disable animated arrow scrolling. More models append to the same row; filters reset its position.

## Thumbnail authorization

The existing 16 Creality references have no thumbnail assets or recorded image permission. They display a compact neutral image-unavailable mark, not the cat mascot, invented geometry or copied creator photos. The public [category page](https://www.crealitycloud.com/model-category/3d-print-all) is a discovery source, not permission to redistribute its photographs. No officially provisioned Creality API/embedding integration or creator thumbnail authorization has been supplied. Model-file licensing alone is not treated as proof that a separate photograph may be reused.

An MFA-authorized catalog admin can upload a creator-authorized JPG/PNG/WebP through the existing uploader, affirm upload permission, select the image, and add **Public thumbnail permission citation** plus the existing license-review evidence. Record the creator/license source and the scope permitting website display. This citation is public catalog metadata; do not paste private contracts, personal contact details or credentials. Keep private evidence in an approved private system and use a public reference here. Image authorization is independent of commercial-print permission. A reference remains unavailable for orders and cannot expose a mesh, price or lead time after a thumbnail is added. The database and validation schema require at least 20 characters of image authorization evidence for a reference image.

Images are served from existing authorized private assets through the public catalog image route. No external URL proxy, protected endpoint scraping, automatic image hotlinking or third-party model downloading is introduced. Images load lazily, have fixed dimensions, fall back on load error, and can open in a keyboard-accessible local image dialog. Creator, original source and available license links remain on the detail page. To revoke a reference image, clear its selected image and save a review note; removing its authorization citation alone cannot leave the image published. Image responses retain the existing maximum 60-second cache lifetime.

## Inquiry boundary

Migration `202611060015_catalog_carousel.sql` adds `catalog_models.image_permission` and private `catalog_inquiries`, preserving all existing catalog, order, quote, asset and license-review records. It updates only the reference image constraint and existing catalog-save function. The latter records image permission in the existing append-only review evidence.

On a reference detail page a customer can send an **inquiry**, after MEMO authentication, with name/contact email, desired dimensions in mm (positive and at most 260 per axis), requested black/white/grey PETG color, quantity 1–100 and notes. Requested color is a preference, not a stock promise. Authentication preserves entered form values. Submission is rate-limited and idempotent; retries use the same key, with a new key if the model changes. It never creates an order, quotation, payment obligation, model download or permission claim.

The database builds an immutable snapshot of the actual model title, creator, source URL, license/status, image asset reference and public image permission. Customer UUID and account email derive from the authenticated identity/JWT. Contact details are customer-provided. Extra submitted JSON fields are discarded. Client-supplied title, image URL, commercial approval and pricing cannot override the snapshot. RLS permits customers to read their own inquiries and MFA-authorized admins to review them; anonymous callers and cross-customer reads are denied. Direct table insertion/update is not granted to customers. The existing commercial-license, printability, MFA, CSRF and quote/order gates remain enforced.

Admins review the latest 100 inquiries in **Models**, alongside the existing catalog editor. The panel includes customer/selection/source/license/image metadata. There is deliberately no inquiry-to-print-order shortcut: obtain commercial permission, review feasibility and stock, publish an approved model, then use the existing quotation/order workflow. Reference inquiry receipt explicitly states that it is not a print order.

## Checks

Unit/database checks cover image permission requirements, admin MFA, reference non-orderability, immutable server-built inquiry snapshots, identity mapping, extra-field stripping, idempotency, RLS, anonymous access and invalid/hidden-model inquiries. Desktop/mobile browser checks cover stable card dimensions/loading height, long text, dark mode/four languages, arrows, keyboard, horizontal trackpad and Shift+wheel, touch swipe, lazy/broken images, dialog Escape/focus, local detail navigation and form retention through authentication. Test images are synthetic fixtures, not shop listings or creator assets. Connected production thumbnail display remains dependent on real authorization and an admin-supplied image.

Detailed missing-image investigation and per-model status: [thumbnail investigation](thumbnail-investigation.md). The dedicated licensed-thumbnail action on an existing admin model page validates and attaches stored image bytes atomically; a private preview shows the actual uploaded JPEG.
